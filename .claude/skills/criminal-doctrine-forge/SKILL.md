# 刑法学说锻造（Criminal Doctrine Forge）

## 为什么存在这个 skill

民法（请求权基础方法）是收敛学科：通说稳定，AI 直接涵摄给结论即可，`legal-concept-forge` / `legal-system-forge` 足够。刑法的总论处处是学派竞争，AI 的默认倾向是把各学说**揉成一个「综合答案」**——这就是「统合」问题：看似都提到了，实则没有一个学说被认真对待，也没有任何结论可追溯。

本 skill 的职责：**把每个学说当作独立的价值立场，逐个给出结论，再做对照**。这是输出契约，不是可选增强。

## 核心禁令

1. **禁止统合**：当问题存在学说竞争时，不得把各学说压缩成一句「综合答案」或「一般认为」。每个学说必须有自己的结论行。
2. **禁止无出处归位**：提到某学说的代表学者、法考立场或条文时，必须标注来源（书 + 页码，优先来自 legal_ai 检索证据）；检索不到的标注「待核验」，不得编造。
3. **禁止价值改写现行法**：学理分析不得改写法条、司法解释或法考标准答案；先给现行法基线，再展开学说与评价。

## 输出结构（强制，按顺序）

对任意刑法问题，按以下七段输出。无争议的问题允许压缩，但必须显式声明「通说一致」，不得跳过声明。

### 一、争议判定

- 该问题是否存在学说竞争？
- 若有：竞争的核心分歧是什么（价值立场、体系前提还是解释方法）？
- 若无：直接声明「通说一致」，跳到第三段。

### 二、现行法基线 `[现行法/法考结论]`

- 相关法条（条文号 + 内容要点）、司法解释与通说。
- 法考（客观题/主观题）在此问题上的标准立场。
- 条文未核验时明确标注「条文待核验」。

### 三、学说对照表（核心段）

每个学说是表格的一行，列：

| 学说 | 代表学者 | 价值立场/规范承诺 | 核心论证 | **该学说下的结论** | 来源（书/页） |
| ---- | -------- | ----------------- | -------- | ------------------------ | ------------- |

- 「该学说下的结论」必须是对当前问题的**明确答案**（构成/不构成、既遂/未遂、一罪/数罪等），不得留白或写「视情况」。
- 来源优先写 legal_ai 检索到的书与页（如：张明楷《刑法学》6上 p.XXX）；无检索来源时写「待核验」。
- 对每个学说，可给出一条其**最强反对意见**（简短，可并入「核心论证」列或单独小节）。

### 四、法考采信与理由

- 法考实际采信哪家（或哪家为主、哪家在分论例外），为什么。
- 一句可记忆的速记判断句。
- 若法考立场与学术主流不一致，明确点出。

### 五、德国法接口

- 德语术语（有把握才写，否则标「待核验」）。
- 德国主流立场（罗克辛 / 耶赛克体系中的位置）及与中国立场的差异。
- 差异背后的体系原因（如阶层体系 vs 四要件、客观归责 vs 相当因果）。

### 六、边界与变体

- 2 个边界案例：一个「看起来像 A 实为 B」，一个「看起来像 B 实为 A」。
- 区分该争议的关键变量（不超过 3 个词）。
- 1 个变体练习（改一个事实，看结论如何翻转），留给用户自测。

### 七、落盘（可选）

用户要求写入 Obsidian 时，写入 `study_note/刑法/` 或用户指定目录，使用稳定标题与双向链接，不覆盖已有笔记（同名自动加序号）。

## 工作流程

1. **识别输入**：概念 / 法条 / 学说名 / 真题 / 错题 / 案例 / 自创模型。
2. **判定争议性**（对照 `references/controversy-seed.md` 中的争议清单）：命中争议点 → 完整对照；未命中 → 声明通说一致并直接给结论。
3. **检索证据**：用 legal_ai 检索并按学说归位——
   ```powershell
   python -m legal_ai search "争议关键词" --limit 8 --format json
   python -m legal_ai context "学说关键词 结论" --limit 6 --format json
   ```

   需要单书视角时加 `--book-id` 过滤（如 `zhang-criminal-law-6e-v1`）。
4. **生成对照表**：按第三段模板，逐学说给出结论。
5. **判定法考立场与德国接口**：第四、五段。
6. **写边界案例与变体**：第六段（面向场依存型学习者，案例先于抽象）。
7. **落盘或收尾**：第七段 + 一个可执行的小练习。

## 检索与归位规则

- 检索结果若同时含多本书/多个立场，按作者归类到对应学说行；不要把所有句子堆进同一行。
- 某学说的权威著作不在索引（如罗克辛《德国刑法学总论》尚未 OCR 入库）时：该行来源写「待核验：罗克辛卷未入库」，并提示可 OCR 入库后补齐，不编造页码。
- 观点归属不确定时写「转述待核验」，区分「原书主张」与「他书转述」。
- 现行法条文与司法解释必须核验；未核验写「条文待核验」。

## 与多 Agent 分工的关系（可选）

本 skill 的输出契约兼容两种用法：

- **单 Agent 全对照**（默认）：一个会话完成全部学说 → 法考结论 → 德国接口。
- **按立场分工**（德国研究生阶段、且罗克辛/耶赛克入库后）：为每个学说开独立会话，各自用本 skill 的第三段模板只输出自己那一列，最后汇总对照。每个立场会话的 prompt 模板：
  > 用 $criminal-doctrine-forge 分析 [问题]，但只输出「[某学说/某学者]」视角的结论、论证与最强反对意见，其他学说只列名称不展开。
  >

## 表达规则

- 默认中文；语言专业、直接、克制。
- 先短定义再展开；关键概念用粗体。
- 法考问题明确区分「考试判断」与「学理深化」。
- 案例先行于抽象规则（场依存型学习者设计）。
- 对每个学说给出结论时不得用「各有道理」搪塞；若证据不足以裁决，明确说「此处材料不足，结论待核验」。

## 本地项目约定

- 检索命令经 `scripts\run_legal_ai.ps1` 运行（仓库根目录）。
- 写入优先目录：`study_note/刑法/`、`法学攻克系统/概念定义词典.md`。
- 争议种子清单：`references/controversy-seed.md`；学说对照模板：`references/doctrine-contrast.md`。
